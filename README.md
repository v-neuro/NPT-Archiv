# Digitale NPT Archiv · 0.9.0 synthetic pilot

A new project, separate from the iPad assessment app. The handoff snapshot remains unchanged. A static, German-first browser app stores original CSV/PDF exports, patient/stay assignments, revisions and history in a hospital-selected folder. **No patient-data backend, browser database, telemetry, installation or extension.**

For the guided Mac workflow, start with [QUICKSTART](docs/QUICKSTART.md). The latest saved continuation notes are in [CHECKPOINT](docs/CHECKPOINT.md).

Version 0.7.0 imports **one patient and one stay at a time**. Enter the iMed Patienten-ID and Aufenthalts-ID once for all selected files, plus the assessment type for new examinations. An existing patient is highlighted with their examination count/dates and requires one confirmation. A new patient is created only when saving. PDFs attach automatically when their first 50 letters/numbers match a CSV after ignoring separators and repeated extensions; mismatches/ambiguities block saving and offer replacement. No per-file assignment checkboxes or PDF reason fields are shown. New imports require a nonblank Bearbeiterkürzel, saved as the import record actor. Examinations can be excluded and included again without deleting originals; the routine list and patient comparisons omit excluded data, while patient history marks it explicitly. The user reported a successful initial hospital infrastructure trial; the full storage/restore acceptance procedure remains pending.

The new Startseite opens on launch and through the top-left logo. With no library it links to Bibliothek öffnen; with an active library it shows total patients and examinations, including excluded examinations, without double-counting CSV revisions. Count cards open the full matching lists with previous filters cleared. Library selection and patient content remain in memory/folder files only.

Version 0.8.0 replaces the fixed 11-measure assessment summary with **all imported fields** from the selected CSV revision, organised into collapsible demographic, examination and per-test sections. Test versions/scoring modes appear alongside numeric results, flags and notes; original field names and raw precision remain visible. Missing and explicitly empty values stay distinct. Additional/unknown fields have their own section, and the technical raw-cell view remains available below. Display-only change: no archive writes, schema migration or clinical recalculation.

Version 0.9.0 defaults patient comparison to **Alle Messwerte**, first in the selector. The grouped table has one row per eligible numeric performance field and one column per included/type-matching examination. Search narrows the available fields and all-mode rows; an individual field remains selectable. Raw strings/zero/missing values and source hints are preserved. The unselected-patient placeholder card and the requested library-path/CSV-scope helper paragraphs have been removed; export selection/scope behavior is unchanged.

The user's supplied favicon-red.png replaces the sidebar n/wordmark and remains the home button. The original 2330×1664 image is bundled unchanged as icons/brand.png. Aspect-preserving, square PNG variants and a multi-resolution favicon.ico cover browser/shortcut use; Apple touch icon and a local site.webmanifest declare the same artwork. Manifest display stays browser, with no service worker, installation or offline dependency. Source/build assets are local; scripts/create-icons.mjs is a Mac development-only regeneration helper using sips, never run by the normal build or hospital PC. The web host and local preview allow the local manifest and provide its MIME type. Actual Windows/managed Edge desktop-shortcut appearance remains a hospital acceptance check.

## Current result

- Capability gate, explicit folder selection, permission checks, synthetic write/close/read/reopen probe and recovery instructions.
- The optional probe appears only after folder selection, checks that same handle without another picker, and keeps step-specific errors visible. A new archive is created explicitly after selecting its empty folder. Once a library is active, its screen shows the selected folder name and a close action; opening/creation/probe buttons are hidden. Browser APIs do not expose the full OS/network path.
- Guided three-step import: choose one patient’s files, enter the shared patient/stay assignment, then save. New CSV imports require one of the seven staff-selected assessment types; both examination lists and patient histories filter by type. Existing unclassified records remain explicitly unassigned.
- Compact, rebuildable folder indexes and on-demand source details reduce routine opening memory/I/O. Patient comparison values and original reports are verified on access; full integrity checking and backup remain available.
- Single-patient CSV/PDF import with explicit shared IDs, existing-patient history/confirmation, 50-letter/digit filename-prefix PDF links, duplicate detection and reviewed source revisions/collisions. Invalid files and unmatched/ambiguous PDFs block the complete import until replaced or explicitly removed; no patient is created on a failed preview.
- Numeric patient and stay identifiers are independent strings (leading zeroes survive). Patient identifiers stay on the PC and are never inferred from initials, age or iPad sessions.
- Durable originals, selected revisions, patient corrections, reversible exclusion status and attachment links in a verified append-only commit chain. Reselecting the folder reconstructs the archive after browser-site-data deletion.
- Searchable assessments, live partial-ID patient matching (click or keyboard selection without a separate dropdown), patient history, grouped source values, cautious source-value comparison and a bundled PDF.js canvas viewer. No PDF scripting, interactive links, forms or embedded attachments are activated.
- Full integrity inspection and verified copy to another empty folder, preserving both referenced and unreferenced files. The copy can be reopened independently. No automatic deletion, garbage collection or commit repair.

This is a **synthetic milestone build**, not a hospital production release. Native managed Edge permissions, the actual network share, approved hosting and backup-restore behavior need the [hospital acceptance procedure](docs/ACCEPTANCE.md). Development automation simulates the external picker/permissions while writing to real temporary disk folders; it does not verify Windows network-share semantics. There is no general power-loss or multi-PC transaction guarantee.

## Hospital use / delivery

IT serves the contents of `dist/` from a separate approved static **HTTPS origin**. That can be an approved external static host if the hospital cannot provide internal hosting. The existing Vercel-hosted producer working there establishes internet access; it does not establish approval or folder permissions for a new origin. No hosting account or site has been created or deployed by this project.

For Vercel, import this repository as a new project, keep the repository root as the Root Directory, and deploy. The included `vercel.json` selects the Other/static preset, installs locked dependencies without lifecycle scripts or optional native packages, runs tests and the build, and publishes only `dist/` with the documented response headers. No environment variables or database are required. See [Vercel setup](docs/HOSTING.md#vercel-setup). A successful deployment still needs a synthetic browser/folder trial on its actual URL.

Staff only open the URL in existing **Microsoft Edge**, choose the hospital network folder, and grant directory access. Firefox shows the capability/recovery screen; it cannot write this archive. Do not double-click `index.html` or use `file://`. No Node/Python/Docker/localhost service, extension or PWA installation is required on the hospital PC. Internet is allowed for application delivery; offline reopening is not promised. Patient data stays in folder files and browser memory. Browser storage is not used for patient content or required handles.

`npm run export:hospital` creates a new versioned folder under `releases/` with matching static-application, source-code and hospital-test-kit ZIPs, SHA-256 checksums, release metadata and available browser evidence. Source and synthetic fixtures stay separate from the served static application. The bundles contain no patient archive or generated practice library.

Use “Neue Bibliothek anlegen” to select a new empty folder. The optional write/read probe reuses this selection. Click “Bibliothek hier anlegen” in the selected-folder card; this reuses the selected handle and opens import. A probe alone does not initialize archive files. Existing archives offer “Bibliothek öffnen” instead. Opening an empty folder through the existing-archive button also offers explicit creation without repeating selection. Unrelated or unreadable contents are never initialized over. Libraries open in “Ansichts-Modus”. Click the mode button beside the library name, tick the sole-editor statement in the popup, then choose “Fortfahren” before importing/changing records. Readers need neither a writer lock nor confirmation. Follow Importieren → Dateien auswählen → Patient & Aufenthalt → Speichern. Enter one numerical patient ID and stay ID for all files, select the assessment type for new examinations, confirm adding to an existing patient when prompted, and supply Bearbeiterkürzel in the final save step. PDFs are matched by the first up to 50 Unicode letters/numbers of the filename, case-sensitively after NFC normalization and removing separators and repeated trailing .csv/.pdf extensions. Ambiguous matches remain blocked. Original filenames/bytes are retained; no content-based identity is inferred. Clear browser-site data and reopen the same archive folder. Patient links, stay IDs, revision choices and original PDF links must still be there.

“Untersuchungen” has search, assessment type and archive status filters (included/excluded/all). “Messwert / Feld vorhanden” now offers only fields with numeric performance values in at least one selected source revision in the archive, including excluded examinations. Numeric scores, individual items, counts and timings are eligible; notes, identifiers, demographics, versions, modes and completion flags are omitted. It does not use a fixed list of measures. Filtering checks numeric raw cells in the selected version, including zero. Patient comparisons use the same rule scoped to that patient’s included examinations and the active type filter, with searchable choices and exact source values loaded on request. This classifies fields for display; it does not extend parser normalization, establish completed administration or judge clinical comparability. Projection 3 stores numeric eligibility positions without copying unknown raw values or long notes. The redundant patient dropdown was removed.

Both “Untersuchungen” and “Patienten” provide explicit CSV-selection checkboxes, “Alle gefilterten Treffer auswählen” (across every page/result, not just visible rows) and “Exportiere als CSV”. Selection stays while filters change; hidden selections are counted and can be cleared. Examination exports contain exactly the checked sessions; use the status filter to select excluded ones. Patient exports contain **every examination of the checked patients**, including excluded examinations and types hidden by the history filter. Each row contains archive patient/stay IDs, date/type, exclusion flag, selected-source identity/provenance and **all original CSV fields**, including notes and unknown fields. Source fields are unchanged apart from recorded spreadsheet-formula protection. Missing/absent/quoted-empty distinctions remain explicit. The CSV is a derived analysis file, **not a backup or importer input**; PDFs and older revisions remain in the library and verified full backup. Read [CSV format](docs/CSV-EXPORT.md).

Version 0.7.0 adds a persistent import completion receipt with patient/stay IDs, examination types, CSV/PDF and skipped counts, plus actions for next patient, details and reports. The next-patient action clears the previous files/IDs. Single/multiple original PDFs can also be opened directly from examination lists and patient history; absent reports are explicit. Both measurement selectors now group fields by test and supply readable labels for every eligible field in the handed-over catalogue while retaining exact source keys. Unknown future fields remain visible under “Weitere Felder” without invented clinical meanings or units.

Viewing is the default: opening a library holds no writer lock. The top-bar mode button switches between turquoise “Ansichts-Modus” and solid-red “Bearbeitungs-Modus”. Entering edit mode opens a compact native dialog with an unchecked sole-editor checkbox; “Fortfahren” stays disabled until checked. Only continuing requests write permission/lock and activates editing after a fresh view check. Cancelling/Escape leaves viewing active. Clicking the edit-mode button returns to viewing and releases the lock, with explicit discard confirmation for unsaved imports. The adjacent refresh icon (“Ansicht aktualisieren”) refreshes the compact overview/details and rechecks retained import drafts; it is not a full integrity check. Multiple readers can browse/export while a single writer works. Cross-PC writing is still unsupported.

Interrupted saves retain an in-memory attempted record ID/checksum and persistent saved/not-saved/uncertain feedback. “Verbindung erneut prüfen” reuses the selected folder and checks the full authoritative chain/originals before resolving the attempt. A record that reached disk before acknowledgement was lost is recognized without replaying the save. A missing attempt in a valid matching chain is reported as absent in the checked state; damaged/forked/rolled-back evidence remains uncertain. Retry remains blocked while checking is needed. Optional folder reselection verifies library identity. No automatic repair, deletion or browser-persistent save journal is added; after a browser restart, recovery still comes from folder files and normal duplicate/revision checks.

The hospital handoff includes **hospital-test-kit.zip** with a printable German TESTPLAN.html, IT-PROTOKOLL.html, four staged synthetic import exercises, a 7-patient/21-examination practice library and FREEZE.json recording the exact source/static ZIP hashes. No test archive enters the hosted app. Keep the frozen artifacts for the hospital trial and record deviations against that version. Read [hospital testing](docs/ACCEPTANCE.md).

The refreshed interface uses a light sidebar, solid red active actions, local outline icons, softer surfaces, completed import steps, active filter chips and short interaction feedback. Reduced-motion preferences are respected. No external UI/font assets were added.

The color palette follows the user's Corporate Design Kurzmanual 2024, pages 14–15. See [color mapping](docs/DESIGN.md); logo structure and fonts are unchanged.

The archive folder must be **outside every web root, Git checkout, `dist/` and public hosting directory**. Keep real exports out of this development project. Hospital filesystem permissions and IT backup/encryption procedures protect the data; this app adds no authenticated identity or folder encryption.

## Architecture and limitations

Read [archive format and recovery](docs/ARCHITECTURE.md) and [deployment headers](docs/HOSTING.md). One writer is a necessary operating boundary. Web Locks block a second tab in the same origin/browser profile; they cannot coordinate PCs, profiles or another origin. Head-change/fork detection reduces accidental conflicts and fails closed; a network lock file is not treated as a distributed lock.

Records have no retention expiry or fixed archive-count limit. Version 0.7.0 opens a compact folder index and loads full source details on demand. All source records and originals remain authoritative and reconstructible; no browser database is required. See [index design and integrity boundary](docs/INDEXING.md). A normal cached overview is not a full integrity check: source size/mtime fingerprints detect ordinary changes, while same-size/same-time modifications require source access or full verification. Full checks and backups bypass the index. On a 7,800-assessment local synthetic benchmark with projection 3, warm indexed opening took about 1.49 s and 95 MiB retained Node heap (cold rebuilding: 3.84 s, 86 MiB). These use tiny PDF fixtures and do not establish hospital network performance or unlimited practical capacity.

The handoff describes actual producer source at commit `6d72df1872049089e298ff9a082db412f8f64351`, not a verified deployed exporter. CSV source release remains **unknown** even when its header signature is recognized. Legacy truthiness/rounding omissions cannot be recovered. Backup, archive schema, app and parser versions are independent.
