# Folder format v1 and failure boundaries

## Durable identities

`archive.json` identifies `digitale-npt-folder-archive`, schema version 1, a random archive UUID and creation timestamp. New archives are initialized only in an explicitly selected completely empty directory. Existing/unreadable/unknown manifests are never replaced. A failed initialization requires inspection or another empty folder.

```text
selected hospital folder/
  archive.json
  objects/<first-two-hash-characters>/<sha256-of-exact-bytes>.csv
  objects/<first-two-hash-characters>/<sha256-of-exact-bytes>.pdf
  records/<random-commit-UUID>.json
  indexes/v1/<generated-cache-hash>.json  # disposable, fully rebuildable
```

Internal names use generated UUIDs and hashes only. Original filenames, source session IDs and numeric hospital identifiers never become paths. A shared original object can support multiple history references. Patients, stays, source sessions, internal assessments, source revisions and attachment identities are distinct. Revisions record complete raw parsed cells (including quoted/missing distinction), explicit typed fields, warnings, unknown fields, parser version, source date/time text, nullable timezone and producer version, header signature and semantic hash. No transformations are written back to original bytes.

Each commit is `{payload, checksum}`. `checksum` is SHA-256 of UTF-8 `JSON.stringify(payload)` with its persisted property order. Payload includes format `digitale-npt-folder-archive-commit`, `schemaVersion:1`, archive ID, commit UUID, parent checksum or null, ISO creation time, self-entered actor label (required for new UI imports since 0.4.0; legacy records and other operations may be empty), and ordered operations. Hashes detect accidental corruption, not authorship. A user who can edit the folder can also rewrite checksums.

Operations: `patient.create`, `assessment.create` (including numeric stay ID, nullable patient link and optional assessmentTypeId), `revision.add`, `revision.select`, `patient.link` with reason, `stay.update` with reason, `assessment.type.set` with reason, `assessment.exclusion.set` with boolean `excluded`, `assessment.clinical.set` with a complete clinical annotation, `attachment.add`, `attachment.unlinked`, and `attachment.link`. Every patient/link/revision/attachment change is durable metadata. No patient lookup is a browser-only index. The patient identifier and stay identifier are decimal **strings**, not numbers. Stay IDs need not be unique per assessment: multiple assessments in the same stay are valid. Patient identifiers are unique exact strings within an archive. Leading zeroes are significant; institutional normalization rules remain pending.

## Commit protocol

1. Read/validate files and review the selected subset in memory. Reject malformed CSV and unsupported inputs. Validate all operations as one transaction before any original is written.
2. Re-read the manifest, record inventory/fingerprints and unique chain head. Validated compact projections may be reused; changed/uncached source records are read and checked in full. A stale head, recovery error or wrong archive identity blocks writing.
3. For every new original, hash the imported bytes, create its generated path, write, close, reread and check length/hash. Never overwrite an existing object. Verify existing deduplicated objects too.
4. Check the chain head again. If it changed, leave written unreferenced objects in place and stop.
5. Create the unique immutable commit file **last**, close it, reread and validate exact bytes/checksum.
6. Re-scan the archive. Show success only if the new commit is the sole valid head with the new transaction’s required originals valid. Unchanged earlier originals are verified on access or full integrity check. The UI is rebuilt from that scan, with no authoritative index update needed.

These operations do not form an atomic directory transaction. File stream close is not a promise that a network server has durably flushed to physical storage. Sudden power loss, SMB caching, disconnects and filesystem-specific behavior require actual IT testing. If close/readback fails after a commit may have succeeded, the session goes read-only; reopening determines whether it exists. Never blindly retry against stale memory.

Every committed transaction is applied to a tentative view with only touched entity collections copied. If an operation or object reference fails, none of that transaction's changes enters the accepted view. Unrelated prior commits remain available.

## Deterministic replay and recovery

During full integrity checking, enumerate records; check bounded JSON size, safe keys/nesting, supported versions, archive ID, filename UUID, checksum, parent, operation invariants and required original hashes/lengths. Group by parent checksum, replay from the unique root and accept only a unique next child. File enumeration order and local clocks never select a winner. A fork stops at the last common valid parent. A malformed/unrecognized commit, missing/corrupt original, detached chain or unknown operation forces read-only mode and a visible issue. Unknown manifest schemas do not initialize or write; use a matching application version or verified restore.

Normal indexed opening follows the [index design](INDEXING.md): validate source inventory/fingerprints, cached envelope/version and unique chain; validate uncached records from source. Source details and original CSV/PDF bytes are checked on access. A same-size/same-time edit can remain unnoticed in a cached overview until access/full verification. The cache is not an authentication or integrity boundary.

During full checking, unreferenced objects are reported separately and remain untouched. They may result from interrupted pre-commit writes. The app performs no cleanup, deletion, automatic rollback, fork choice or repair. Failed first commits can leave objects and an otherwise empty valid archive; malformed final commits require recovery. Restore the **entire** folder to a different location using IT backup procedures, then open and fully validate it. Do not merge two restored copies by copying individual records together.

Future migrations must be copy-based to a new archive/format, retaining all originals and old metadata. This release refuses unknown archive schemas/operations; it does not attempt source migration. Version 0.7.0 opens older schema-1 archives; older apps encountering the new type-assignment operation must remain read-only. Index versions are separate and disposable. Saved app/parser versions make reprocessing explicit rather than silently revising scores.

## Import decisions

New CSV imports require an explicit staff-selected assessment type from the seven-entry catalogue. Legacy records without one remain null; no type is inferred from administered tests or filenames. A correction is an append-only `assessment.type.set` event with a reason. Assessment and patient/history filters use this durable metadata. Clinical source values and original bytes remain unchanged. See [INDEXING](INDEXING.md) for schema/older-app behavior.


CSV grammar is strict semicolon CSV with escaped double quotes and embedded newlines, optional BOM and CRLF. One assessment row per producer file. Header-name mapping accepts reordered, reduced and future columns, rejecting duplicates, unsafe/invalid names, invalid quoting and inconsistent lengths. The raw representation preserves missing unquoted cells, quoted empty strings and formula-safety apostrophes. The small numeric registry types only explicitly reviewed fields. Unrecognized numeric text remains text with a warning. German dates are explicitly validated and stored as local calendar dates; no UTC offset is invented.

Identical file bytes are reported and skipped. Different bytes with the same source session are reviewed as equivalent formatting or changed-value revisions. Selection is explicit; keeping a new revision does not silently change the displayed one. Patient/stay conflicts require separation or a later documented correction. A separated assessment retains the original source session ID. Two CSV exports of the same session in one batch require sequential imports for a stable review baseline. No demographic auto-merge occurs.

Version 0.3.0 follows the user’s updated import decision: one patient and stay per import. `planPatientImport` resolves the exact numerical patient-ID string, lists their prior examinations and requires confirmation if they already exist. `buildPatientImport` recomputes this plan before creating any operations. All new examinations share this patient/stay assignment and the explicitly selected assessment type. A new patient is created in the same durable commit, never during preview. Known source-session or duplicate ownership conflicts cannot silently relink another patient or stay; explicit source-session separation or a later documented correction is required.

PDF attachment follows the updated user-authorized **50-letter/number prefix** rule: remove all repeated trailing `.csv`/`.pdf` suffixes case-insensitively, normalize the remaining text to Unicode NFC, retain only Unicode letters/numbers, and compare the first up to 50 code points case-sensitively. A nonempty key and exactly one target are required. Suffixes such as `.pdf.pdf` and differences beyond the prefix are accepted. Prefix collisions are blocked. No demographic inference or content-based identity claim is made. Uploaded CSVs take precedence; a duplicate CSV can resolve its existing assessment by its byte hash. PDF-only imports may match an archived CSV only for the entered patient and stay. A mismatch or ambiguous target blocks saving and offers replacement, adding the CSV, or removing the file. Replacement files are re-inspected. The helper recomputes links rather than trusting suggestion/target fields.

Automatic attachment metadata records `method: filename-prefix-50` and a machine-generated explanation of the comparison rule; it does not claim staff manually checked the PDF. Earlier `exact-filename-match` provenance remains unchanged in existing records. Relationships remain assessment-level, without asserting a particular CSV revision/export moment. Reusing identical PDF bytes for another examination creates a separate durable attachment link; an existing identical link is skipped. Original object bytes are still deduplicated by hash. Old unlinked attachments remain readable and can be assigned through recovery, but new imports no longer create unresolved patients or unlinked PDFs. The previous low-level reviewed-import builder remains for format compatibility and regression tests; the app uses only the single-patient builder.

Any invalid file or unresolved revision/PDF conflict blocks the complete import until the user replaces or explicitly removes that file. Source-file signature checks are not proof that a PDF is valid; viewer failure never removes the stored original.

Limits: 100 files / 128 MiB batch, 32 MiB/file, 8 MiB/CSV, 2,000 columns, 1 MiB/cell, 16 MiB/commit, 500 operations/commit, bounded JSON nesting. Oversized content is rejected explicitly. Nothing is truncated.

## Reversible exclusion and required import actor

An assessment starts with `excluded:false` when replaying old or new creation records. `assessment.exclusion.set` validates an actual boolean and changes only this metadata flag. Exclusion and inclusion are separate append-only records with commit time/actor metadata; no original object, revision, patient link or attachment is deleted. The whole assessment, including all source versions, shares the flag. Reimporting a duplicate, adding a report or selecting a revision does not implicitly include an excluded assessment again.

The default examination list includes only included assessments; the visible archive-status filter can show excluded-only or all, and combines with text/type/measure filters. Patient history retains excluded entries with a badge; patient source-value comparisons omit them and clear cached values after a status change. Backup and integrity verification retain and check all data regardless of exclusion. Schema remains 1; older apps encountering the new operation must fail read-only and preserve the folder. The derived projection copies this operation as metadata, without a new projection schema.

New one-patient imports require nonblank `actor` text of at most 100 characters. The UI keeps the field visible in the save step and prevents saving when empty/whitespace-only. The builder validates before any write and returns the trimmed actor for the durable commit. Prior records with empty actor remain readable, and the requirement does not invent an authenticated user identity.

## Concurrency, backup and privacy

Web Locks are held for the opened archive UUID and released before switching. Same-profile second tabs are read-only. Other PCs/profiles/origins are outside that lock's scope. Stale-head checks and fork detection **do not make simultaneous writers safe**. The operator confirms exclusive writing across PCs for each open session.

Verified app backup requires an empty target. It recursively copies all source files byte-for-byte with readback, including unreferenced/recovery files, checks the source head again and writes the manifest last. It validates the target's chain and originals before success. If interrupted, do not call that partial target a verified backup; preserve/inspect it and use another empty target. A damaged source needs a full IT filesystem copy before recovery, rather than an app backup that would endorse an incomplete state. IT's automatic network-drive backup is the primary backup; a network drive by itself is not a second copy. There is no deletion or retention-expiry feature.

No IndexedDB, localStorage, service worker, telemetry or patient-content fetch exists in the application. Files live in the selected folder and runtime memory. On browser-data deletion the folder handle is simply selected again. Static assets may be cached by the browser/host; they contain no patient data. PDF input is passed as bytes to a local sandboxed canvas renderer; PDF actions, links, forms and scripts are not instantiated. Built-in fonts/CMaps/WASM are bundled local assets. Downloading an original uses `application/octet-stream`; opening that downloaded file in another program falls under the hospital's approved viewer policy.

Archive files are unencrypted by this application. Controlled hosting code updates, managed browser/Windows security, filesystem ACLs, IT encryption, backups and approved transfer are necessary operational controls. A self-entered actor label and writable event files are traceability, not authentication or a tamper-proof audit log.

## Archive-driven field choices

“Messwert / Feld vorhanden” and patient comparisons use the same numeric-performance eligibility rule, based on selected source revisions. Archive filtering includes excluded assessments in the available choices; comparisons omit excluded assessments and respect patient/type scope. Notes and administrative fields are excluded even if their values look numeric. Unknown future numeric fields remain eligible. Selection does not assert completed administration or change the clinical parser’s small typed registry. Every full raw source field remains available in details/exports.

Projection 3 adds numeric-performance positions alongside projection 2’s shared header layouts and nonempty positions. Missing/quoted-empty values do not match, zero does. Old/malformed caches rebuild from supported source; source records/objects/schema are not migrated. See [INDEXING](INDEXING.md).

## Derived CSV exports

Both list pages offer explicit checkbox selection and select-all across all matching results. Selections live only in memory, survive filter/page changes, show hidden-selection counts and clear on library change/close. Examination export resolves exactly the selected examination IDs. Patient export resolves every examination of the selected patient IDs, independently of history filters and exclusion. Excluded rows are never silently dropped; each exported row has an exclusion flag.

The exporter rereads/checks source records, requires the same archive/head as the open snapshot, loads selected examinations from verified CSV sources with a fresh eight-record cache, and builds UTF-8/BOM semicolon rows. It rechecks the head after generation, before offering a local Blob download. Read permission suffices; no archive/cache write occurs. Corrupt or changed sources abort the entire download and show a recheck/reopen path. No partial file is offered. Output has a 128 MiB UTF-8 limit and explicit smaller-selection error; nothing is truncated.

One row represents the selected revision of one examination. Original CSV fields use a union of selected-source headers and retain raw values/precision. Archive metadata uses `archive.` prefixes, impossible in producer headers, to avoid collisions. Empty/absent/missing distinctions and spreadsheet-formula protection are documented in [CSV-EXPORT](CSV-EXPORT.md). No totals, imputations or clinical interpretations are generated. This table is not a full backup and is not producer-import input.

## Viewing, explicit editing and refresh (0.7.0)

Opening/creating a library activates read access without acquiring a Web Lock. “Bearbeiten” requests write permission, obtains the same-origin/profile lock if available, refreshes the folder snapshot, then requires sole-writer confirmation before mutation. Reading/report/CSV actions need no writer ownership. Ending editing releases the lock, with explicit discard confirmation for unsaved import drafts. This permits concurrent readers; it does not add a network lock or support concurrent cross-PC writers.

“Ansicht aktualisieren” opens a fresh compact snapshot, validates library identity, clears full-detail/comparison caches and re-inspects retained input files. Patient confirmation/source-revision choices are reset during re-inspection. Pending-save/recovery states cannot be cleared by this lightweight refresh. A full “Bibliothek prüfen”/connection recheck reads the authoritative records and hashes referenced originals. The UI full check is read-only; missing indexes rebuild in memory and can be persisted on a later authorized save or via the development/core rebuild operation.

## Save evidence, receipt and recovery (0.7.0)

The save ordering/immutable formats are unchanged. Each Archive instance temporarily tracks `lastAttempt`: archive identity, base head, generated record ID/checksum, whether record writing began and not-saved/uncertain/saved outcome. Before record writing, a failure cannot have committed that operation (unreferenced objects may remain). From record-write initiation until verified acceptance, the outcome is uncertain. Success is set only after the saved chain has the intended checksum and new originals have passed their checks. Both compact and full-source commit paths track this evidence.

UI feedback survives menu changes in memory and blocks mutation/import edits while unresolved. Connection recheck reuses the selected handle (or explicitly reselects a matching archive), bypasses indexes, verifies the full chain/referenced originals and compares exact attempted record ID/checksum. A valid later descendant does not erase evidence of the earlier successful save. A rolled-back parent, conflicting checksum, damaged original or unreadable/forked chain cannot establish success/failure and remains blocked. No operation is automatically replayed and no orphan/commit is deleted. Recovered snapshots return to viewing mode; a fresh explicit writer confirmation is required. Retained unsaved input is re-inspected before retry.

This evidence is runtime-only and contains no browser-site-storage dependency. Restarting the browser loses drafts/receipt/evidence but cannot lose a committed source record or patient/attachment links. Reopen the folder and use existing duplicate/revision detection before importing source files again. This is not a distributed transaction or power-loss guarantee.

Import receipts count new examinations, added revisions, added PDF links and skipped duplicates, and retain the affected examination IDs plus entered identifiers/operator in memory. Details/report actions resolve against the current archive state. Original PDFs are length/hash checked before viewing from lists, history or receipts; multiple reports require a small filename choice. The dialog shows patient/stay/date context, never in the URL.

## Optional clinical annotations and age filtering (0.10.0)

`assessment.clinical.set` stores `{assessmentId, clinical:{diagnosis,diagnosisStatus,dementiaType,affectedHemisphere}}` as a separate immutable history operation. All four properties are required; null means unrecorded. Diagnosis and dementia type are bounded text (2,000 / 200 characters); diagnosis status is null/confirmed/suspected and hemisphere is null/left/right/bilateral/unclear. Unsupported keys/statuses are refused during whole-transaction preflight. A later complete set can explicitly clear fields to null. Prior values remain in history. This metadata describes the assessment, independently of the chosen CSV revision, and never changes producer fields or clinical scores.

The import writes annotations in the same record as new assessments, revisions and attachment links. Shared entries apply only to newly created/separated assessments; additional revisions, duplicate CSVs and PDF-only imports do not overwrite existing annotations. The UI shows the dementia field for memory-clinic and hemisphere for both epilepsy types. New imports omit draft values for unrelated types. Later type corrections retain existing annotations; the detail editor continues showing any such recorded fields so they can be cleared explicitly.

Legacy assessment.create records acquire an all-null runtime view, without rewriting source records. Schema 1, parser npt-semicolon/1 and projection 3 stay unchanged: non-revision operations already pass intact through compact projections and their validation/replay. Cold/warm opening, on-demand details, rebuilding indexes, full checks and backup replay the same annotations. Older applications see the unfamiliar operation and fail closed/read-only; do not use them for continued editing after upgrading.

Search text for diagnosis/dementia is a case-insensitive substring; status/hemisphere are exact choices. Filters combine with AND, and select-all-filtered uses the same result set. The age parser accepts inclusive hyphen/en-dash ranges, exact values, >=/≥, <=/≤, >, < and a trailing +. It reads only a nonmissing, nonnegative numeric demographics_patient_age raw cell in the selected revision (decimal dot/comma accepted); missing/ambiguous values never become zero or a current age. Invalid filter syntax produces no matches and a visible correction hint. No source age or score is rewritten.

Tabular exports retain format digitale-npt-tabular-export/1 with four additional named archive metadata columns: archive.diagnosis, archive.diagnosis_status, archive.dementia_type, archive.affected_hemisphere. Status/hemisphere use their stable stored enum keys, null exports as an empty string. Source fields retain their original names/values and missing/absent distinctions. The existing spreadsheet formula escaping and escaped_fields audit also apply to annotation text.

Typed reassignment validates the exact patient identifier, numeric stay, type and correction reason before writes. It emits only changed patient/stay/type operations, optionally preceded by patient.create, all in one existing commit. Empty patient ID explicitly unlinks; new numeric IDs retain leading zeros. No identifier is converted to a number. A no-change submission does not write a record.

Direct detail PDF uploads use attachment.add with filename-prefix-50 provenance and a session-level revisionId:null. Existing identical bytes attached to that assessment are a no-op. Bytes shared with other assessments can still receive an independent attachment link. Original bytes retain the existing verified object-first/record-last protocol, stale-head checks and recovery behavior.

Neueste Änderungen is a read-only projection of accepted state.history operations, including legacy unlinked-report/link operations. No new audit database, filesystem watcher or browser persistence is added. External unrecorded file edits are not claimed as application history. A lightweight pass retains historical patient/stay/selected-revision context and CSV file names/dates. Imported-revision rows use that revision's exported date, while subsequent metadata rows use the selected revision at the time of the event. Patient creation has no examination date. Events appear in reverse accepted-chain/operation order, independent of clock sorting. Edit-day filters use the browser's local calendar for the persisted ISO timestamp; invalid/unknown dates remain undated. Inclusive edit/examination date ranges and case-preserving numeric ID substring filters combine with AND. Reassigned assessment events match historical, old/new assignment and current identifiers; the displayed historical ID records the current ID when different. Pagination bounds rendered rows to 50. Indexes and history rows remain disposable; originals and folder records are authoritative.

Successful settled re-verification feedback receives an in-memory five-second display deadline after the check completes. The report has two restricted components. The HTML renderer is sandboxed with allow-scripts only (opaque origin); the parser is a dedicated static module worker created by the parent. The worker retains the app origin but has no DOM, no folder-picker API, no directory handles and a response CSP with no network connections or further workers. It communicates only with the opaque renderer's private PDF.js port; its global messages are not an application action API. The renderer cannot read parent DOM/storage, navigate the top, open popups or obtain archive handles. Its CSP allows the exact bootstrap/style hashes and Blob renderer modules, no connect/nested frame/worker/font loads.

The frame creates the initial MessageChannel and posts one end to the expected parent origin. The parent accepts only the current frame WindowProxy, opaque origin, unpredictable token, exactly one port and one initialization. A subsequent frame navigation cannot receive the earlier frame's private port. The renderer receives only selected PDF bytes and a private parser port; the parent accepts only bounded generic status messages. Renderer failure/timeouts leave the authoritative original untouched and terminate the worker. All decoding resources are embedded into the worker; strict fetch/synchronous-XHR adapters serve only exact names from that resource map. A single reviewed build-time import replacement maps the two known non-WASM decoder fallbacks to local Blob modules. WASM/ICC/font resources remain available without network fetches. Source dependency files stay unchanged and the build fails on an unexpected worker layout.

The deployment remains one static HTTPS origin with no hospital installation/backend/new domain. App, PDF HTML and worker have separate CSPs; build checks inline hashes against vercel.json. Source, parser, archive schema and projection versions are unchanged apart from the app release. Review the actual iPad PDF output on managed Edge after deployment; bundled synthetic PDFs do not establish every PDF feature or policy combination.
