# Hospital acceptance · synthetic data only

Record Edge version, Windows version/build, approved app origin/release, operator, date, network-drive type/path class (without patient data), permissions/policies, estimated PDF sizes and results. Browser presence alone does not establish working folder access. No real exports until the following workflow is accepted by IT and the clinical owner.

1. **Delivery:** Open the separate approved static HTTPS archive URL in Edge on the Windows 10 hospital PC. Check release 0.2.0. It must work without installations, extensions, localhost services or a PWA. Internet is allowed; no offline availability is promised. Firefox and `file://` should show the unsupported-capability recovery screen. Confirm a separate, controlled update origin/process; do not assume an external host has been approved merely because the iPad app is reachable.
2. **Policy/permission:** Check available capabilities. Cancel the folder picker: no archive or unrelated file should be created. Deny directory write permission: clear recovery message, no import success. IT checks `DefaultFileSystemWriteGuardSetting` and origin-specific allow/block policies if needed. Reselecting the folder is the visible recovery path. Test grant and later revocation.
3. **Actual share probe:** Create an empty synthetic test directory on the proposed network drive. Run “Schreib- und Leseprüfung starten”. Verify creation, stream close, readback, reopen and removal of only the uniquely named probe file. Repeat after a browser restart and after disconnect/reconnect. A successful local-disk test does not establish SMB/network behavior.
   After a successful probe, the folder should remain selected. “Archiv hier anlegen & fortfahren” explicitly initializes it without another picker, then opens import. Switching menus must preserve the active archive. A failed probe must name the failing operation and keep technical details visible. Its uniquely named synthetic text file may remain if cleanup could not complete; no archive metadata is initialized by the probe.
4. **First milestone:** Select another empty test directory and create an archive. Confirm exclusive writer use. Import the included synthetic producer CSV and a synthetic PDF from the producer's actual print/export path. Create numerical patient `00012345` and stay `0006789` (invented). Choose an assessment type, assign the patient, confirm decisions. Assign PDF to that batch CSV, document matching evidence and confirm. Commit. Success must occur only after readback. Open the detail and original PDF; the links must work.
5. **Browser-data deletion:** Close all archive tabs. Clear **all site data** for the archive origin (including IndexedDB, localStorage, cache and handles), restart Edge, open the URL and reselect the archive directory. Confirm patient `00012345`, stay `0006789`, selected assessment type, selected CSV and PDF link. Confirm the original bytes match the transferred source. Site data must not be required for recovery.
6. **Revisions and missing values:** Reimport the same CSV: duplicate reported without another assessment. Import `revised-same-session.csv`; review changed TMT A, preserve earlier revision and deliberately select the new one. Reopen. Check manual PHQ-9 zero, negative VLMT difference, partial Rey without a final score, formula-prefixed Unicode/multiline notes, unknown columns and absent fields. Missing/blank values must not become zero. No clinical total is recalculated.
7. **Assignments:** Correct the stay with a reason; the prior value remains in history after reopening. Create/link another synthetic numerical patient in a later import, then correct the first assessment's patient link. Initials/age do not merge patients. Test unresolved patient import and later correction. Preserve leading zeroes in both identifier types. Confirm the institution's exact identifier-normalization/uniqueness convention.
8. **Attachments and invalid files:** Import a PDF later and assign it explicitly to an existing assessment. Import another as deliberately unlinked; assign it later from “Sicherung & Hilfe”. Alter PDF names to produce ambiguous hints; no automatic links should occur. Try one malformed CSV in a batch: per-file error, explicitly selected valid subset only. Unsupported full backups must be rejected clearly. Obtain a synthetic report through the actual producer print path; the automated minimal PDF is not evidence of producer-report fidelity.
9. **Concurrency:** Open the same archive in a second Edge tab in the same profile/origin: read-only. Close the first, reselect in the second: writer can be acquired. A copy with the same archive UUID uses the same profile lock; switching between them must release/reacquire cleanly. Test two PCs only sequentially. Simultaneous writing from separate PCs/profiles is outside the supported boundary. Read-only views update only on explicit refresh/reopen.
10. **Faults:** Using **copies of synthetic archives**, revoke access, remove write permission, disconnect the share during original/record writes, simulate full-disk/close failure where IT can safely do so, remove/corrupt an original and truncate a commit. Earlier valid state must remain available; errors must block further writes until reopened/verified. A failed or uncertain commit must not be shown as a success. Do not inject faults into the working archive.
11. **Backup and restore:** Copy through the app into an empty second directory; reopen and verify patient links, stay corrections, selected revisions and PDFs. Ask IT to restore an automatic backup into a **different** directory and repeat. Establish frequency, recovery point, restore ownership, access control and retention. Do not overwrite the current archive for this exercise.
12. **Privacy and capacity:** In developer/network tools or IT's approved monitoring, import/view both a normal synthetic PDF and a hostile synthetic PDF: only bundled application/font assets should be requested; no imported content in requests, telemetry, external fonts/images or crash uploads. Test realistic annual and multi-year volumes and actual PDF sizes on the share. Measure open/import/search/full integrity-check/restore duration and browser memory. The current pilot uses complete scans; accept a practical limit and implement a rebuildable accelerator before that limit is approached. It has no expiry/deletion policy.

If blocked: record the exact failed API/policy/storage operation. Keep source exports and archive copies intact. Resolve origin/policy/share access with IT. A manual download-only fallback is not equivalent durable folder storage and is not silently substituted. No score extraction from PDFs, guessed patient identity or browser-only persistence is an acceptable workaround.

For version 0.2.0 also verify that new imports require one of the seven assessment types, older unclassified records remain visible, type corrections survive reopen, and both examination and patient/history filters work. Ordinary indexed opening is a quick overview, not a complete integrity audit. Test the explicit full-check/rebuild path and restoring after removing disposable indexes. Local Mac development continues independently of the timing of this hospital trial.
