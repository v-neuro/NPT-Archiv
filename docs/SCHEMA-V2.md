# CSV schema v2 · 0.14.0

The importer supports the provided digitale-npt examination CSV contract, with header-name mapping, UTF-8/BOM, semicolons, quoted numbers, escaped quotes, multiline fields and CRLF/LF. It retains the existing single-examination-per-file import boundary. Reordered/reduced headers and future fields remain supported. The original file is retained in the existing content-addressed archive under its security, integrity and retention rules. This terminology-bearing CSV is not a FHIR resource.

`export_schema_version=2` selects v2; an absent column selects legacy. Explicit unsupported or empty versions reject that file with an actionable error. The expected `export_missing_reason_system` is `http://terminology.hl7.org/CodeSystem/data-absent-reason`; a missing/unrecognized system is retained and warned about.

`normalized[X]` contains a typed nullable result; `missingReasons[X]` contains its independent nullable missing reason. All observed source columns remain in `raw`, including companions, statuses, diagnostics, entry modes, scoring versions, completion/partial flags and unknown future columns. The explicit field registry covers the 280 observed numeric fields and 44 source 0/1 flags (normalized to booleans). Future fields remain text until their type is reviewed. No truthiness checks create missing scores: `0`, `0.5` and `false` are present values. Quoted and unquoted blanks normalize to NULL; their original CSV representation remains available in the technical view and export.

Known missing reasons are `not-performed`, `unknown`, `not-applicable`, `unsupported`, and `error`. Nonempty values normally have a NULL reason. Empty v2 results without a companion reason become NULL/`unknown` with a warning. Missing companion columns and missing/unknown statuses produce warnings. Contradictory value/reason pairs retain both parts and an error diagnostic. Unknown codes remain metadata, with a warning and a readable fallback label. Malformed numeric and 0/1 inputs retain their exact source text but yield a NULL typed result; a missing reason defaults to `error`. A supplied conflicting reason remains preserved. There is no examiner prompt for unused-test reasons.

Every supported test group has an independent status: `not-performed`, `unknown`, `recorded`, `completed`, or `aborted`. Missing statuses default to `unknown`; unknown explicit codes are retained. The naming-test status is `cerad_bnt_assessment_status`, independent of its `cerad_benennen_aborted` source flag. Notes, versions, zero abort flags and numeric results never establish completion. Available results in interrupted tests remain available. Untouched v2 tests are distinguishable from ambiguous legacy blanks.

The archive performs no clinical score calculation, recognition recalculation, cutoff-to-time conversion or zero filling. Suppressed v2 totals remain NULL. Permitted partial Rey/QOLIE values remain present with their source diagnostics and completion/answered-count flags. Unsupported MoCA education fields remain NULL/`unsupported` when exported that way. Historical nonempty source scores, including historical zeros, are retained without claiming retrospective scoring corrections.

Exact numeric source strings are retained for display/export and canonical decimal revision comparison, including precision beyond JavaScript's numeric representation. Typed numeric results and `aggregateMeasure` calculations use finite JavaScript numbers; they are not arbitrary-precision arithmetic. Canonical comparison distinguishes high-precision values that round to the same JavaScript number, and also distinguishes different malformed inputs. Numeric formatting alone, such as `12.00` versus `1.2e1`, does not create a value difference. Original byte hashes still control exact duplicates. Reason/status changes require the existing explicit revision review; selected-revision and examination ownership rules are unchanged.

## Existing archives

There is no SQL database in this application: authoritative storage is the immutable schema-1 commit chain and original objects. New documents use adapter `npt-semicolon/2`, with derived contract view version 1. Both `/1` and `/2` documents remain readable. On replay, projection building and full-detail loading, older documents acquire typed NULL/`unknown` for blank fields and `unknown` statuses. Nonempty historical source values are never zero-filled, recalculated or silently replaced. Invalid historical numeric text remains in the original/technical view and receives a typed NULL/error diagnostic. Original cell quoting and adapter version stay intact.

The migration builds new runtime objects, without modifying saved envelopes, old semantic hashes or original files. Disposable projection-3 caches rebuild as projection 4, including source provenance, test statuses and compact missing-reason indices. Full reads, cold/warm indexed reads, cache deletion, revision selection and verified whole-archive backup use the same derived rules. Older application versions do not understand the new adapter and should not be used to continue editing these archives.

## Display and analysis

Missing result labels are German: “Nicht durchgeführt”, “Unbekannt / nicht dokumentiert”, “Nicht zutreffend”, “Nicht unterstützt”, and “Ergebnis nicht verfügbar”. Missing cells and test sections without numeric results are gray; version selections/notes/flags alone do not make a section look populated with results. Genuine zero stays visible. Raw source values remain in the expandable technical view. Import warnings appear before committing and in examination details.

Additional examination filters select a test group/status and a field/missing reason. Unknown reason codes are selectable. Filters follow the chosen revision and work with warm compact indexes. Examinations remain in the unfiltered archive and administrative chart counts even if every result is NULL. Existing charts count examinations rather than clinical scores. The nullable-result query helper `aggregateMeasure` operates on full verified documents: result count, mean, minimum and maximum exclude NULL/invalid values, include genuine zero and exclude flagged examinations by default. Empty result sets have NULL mean/min/max, not zero. No clinical imputation is performed.

The derived multirow analysis CSV retains all original columns (including v2 companions/statuses) and source precision, alongside archive metadata and existing spreadsheet escaping. It remains an analysis export rather than a restore/import format.

## Format boundaries

Structured `.npt-backup.json` / `.npt-backup.txt` assessment ingestion was not supported before this change and remains explicitly rejected. No backup envelope/checksum is rewritten and no raw assessment fields are stripped or interpreted. Consequently this archive does not derive results from `collection_version`, `assessed`, or `assessment_complete`. The existing verified **archive-folder** backup copies all source bytes unchanged; it is distinct from a source assessment backup. PDFs remain retained report attachments and are never mined for numeric values or German labels.

Multiple examination rows in a single source CSV remain explicitly rejected; import separate source exports. Hospital-managed Edge permissions and real network-share behavior still require the existing manual acceptance procedure.
